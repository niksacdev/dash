# Why DASH uses Opik and where DeepEval fits

Engineering review · November 23, 2026

**Keep Opik for experiment history and evidence sharing. Evaluate DeepEval as an optional grader when a domain rubric benefits from its existing metrics.** For example, a Manufacturing operator could ask a decision model whether the inspection evidence supports releasing a lot. The answer, the inspection record, and the grader revision belong on the same saved DASH run whichever library calculates the score.

## What DASH originally decided

The original platform specification made Opik optional for trace links and cross-checks. DASH owned the desktop workflow, results, and export. The later accepted ADR chose Opik’s TypeScript SDK for metrics, dataset and prompt versions, experiments, and feedback. SQLite retains the approved objective, case evidence, and device measurements offline. The operator can send a completed run to a chosen Opik destination without invoking the candidate a second time. The ADRs compare rebuilding these APIs, requiring an always-reachable server, and replaying inference during sync. They record no historical comparison with DeepEval. [Original platform specification](../specs/Financial_AI_Eval_Lab_Spec.md) · [Evaluation and offline runs](../adr/0002-opik-and-offline-runs.md) · [TypeScript decision](../adr/0003-typescript-runtime.md)

## How they fit today

| Operator need | Opik | DeepEval and Confident AI |
| --- | --- | --- |
| Run a reusable rubric inside Electron | DASH already uses the TypeScript SDK’s ExactMatch, Contains, and G-Eval with a selected local judge. A custom metric can extend `BaseMetric`. Opik also publishes a Python SDK. [TypeScript metrics](https://www.comet.com/docs/opik/reference/typescript-sdk/evaluation/metrics) | The open-source framework has Python and TypeScript evaluators. TypeScript offers G-Eval, DAG decision graphs, Vitest integration, agent metrics, and model adapters. Its TypeScript package can run metrics without a Confident AI account. The rubric’s selected judge still needs to be reachable. [TypeScript evaluator](https://deepeval.com/blog/introducing-deepeval-typescript) |
| Grade agent behavior | Opik captures traces and spans and attaches feedback. Its trajectory-accuracy guide documents a Python metric with an explicit step sequence and final outcome. DASH’s TypeScript graders can use recorded candidate tool events for an approved check. [Trace feedback](https://www.comet.com/docs/opik/tracing/advanced/annotate_traces) · [Trajectory accuracy](https://www.comet.com/docs/opik/evaluation/metrics/trajectory_accuracy) | DeepEval provides trajectory metrics for completion, planning, and efficiency. Its TypeScript integrations can capture agent span trees. JevEval can grade supplied case fields or the observed trace. Both frameworks need the hosted agent to expose the events a trajectory rubric asks about. [Agent metrics](https://deepeval.com/docs/metrics-introduction) · [JevEval](https://deepeval.com/docs/metrics-jev-eval) |
| Compare versions and inspect results | Opik provides dataset versions, experiments, a prompt library, and trace feedback. The open-source dashboard can run locally with Docker or the operator can use a hosted destination. DASH’s recorded local-service test links two candidate experiments to the same measured dataset and approved prompt versions. [Dataset versions](https://www.comet.com/docs/opik/evaluation/advanced/manage_datasets) · [DASH local deployment](../adr/0004-local-opik-service.md) | DeepEval can read local datasets and persist test-run history to SQLite for Python and TypeScript. The optional Confident AI platform provides versioned datasets, run comparison, tracing, and human feedback. Self-hosting that team platform requires an Enterprise license and container access. [Local SQLite](https://deepeval.com/blog/introducing-sqlite-local-storage) · [Dataset versions](https://www.confident-ai.com/docs/reference/api/v2/datasets/versions/get-dataset-versions) · [Feedback](https://www.confident-ai.com/docs/human-in-the-loop/collect-feedback) · [Platform self-hosting](https://www.confident-ai.com/docs/self-hosting) |

## What deserves a trial

The published `deepeval@0.9.26` TypeScript package exports `JevEval`, `ConversationalJevEval`, and the Noul, Choice, and Score question types. JevEval maps rubric questions and their weights to a score and returns per-question outcomes. Its `systemOneModel` option accepts a custom decision model. A local Liquid D1 endpoint would still need a tested adapter implementing that interface. Pin the rubric, class-to-credit mapping, grader version, and model revision. [Published TypeScript exports](https://cdn.jsdelivr.net/npm/deepeval@0.9.26/dist/metrics/index.d.ts) · [JevEval implementation](https://github.com/confident-ai/deepeval/blob/main/typescript/src/metrics/jev-eval/jev-eval.ts) · [Decision-model interface](https://github.com/confident-ai/deepeval/blob/main/typescript/src/models/system-one/base-system-one-model.ts)

**One default changes the business result.** JevEval assigns 1 when every question is inapplicable. An inspection without the applicable drawing could then look like a perfect assessment in DASH. Require the evidence named by the rubric, record an unscored assessment if it is missing or no question applies, and preserve the decision probabilities. A required dimensional failure must still block release. Run the same saved answers through the decision grader, the established deterministic checks, and G-Eval against blinded human labels. Measure false releases, review coverage, latency, and cost before choosing a default. No models or services were run for this comparison.
