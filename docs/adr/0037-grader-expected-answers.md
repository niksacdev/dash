# 0037. Collect required expected answers before evaluation

**Status** Accepted

## Operator decision

Selecting a reference-based grader commits the operator to supplying an answer or facts that an expert considers correct for the task. In Quick compare, a generated rubric could declare that requirement and still let both candidates run without the evidence.

## Decision

Extend [measure mapping](0028-measure-grader-mapping.md) and [the grader catalogue](0025-industry-grader-catalogue.md). Show the actual saved rubric or rule before selection. Require the expected answer in setup when an explicitly chosen check uses it. Quick compare shares one operator-supplied answer between the two lanes. Store it locally with that run in the same transaction and disclose it to the selected graders that require it. Existing task-and-answer, agent trace and domain scenario requirements still apply. Dataset cases retain their independent labels. Standalone grading asks before scoring.

## Alternatives and consequences

Changing a reference-based rubric to judge the candidate answer alone would change the meaning of its score. Using the answer generated by one lane as a reference would compromise a side-by-side comparison. The exported Quick case identifier derives from candidate input alone. Even a hash of a short expected label could reveal the label to someone reading an export. The operator can pick a different grader or leave a measure unscored. An unsent Quick answer stays in the editing session; after reload it must be supplied again. Historical assessments keep their recorded verdict.
